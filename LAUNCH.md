Этот файл решает две задачи: (1) готовый **системный промт** — вставь его агенту первым сообщением, чтобы он довёл приложение до запуска; (2) **операционный runbook** запуска для человека.

## 1. СИСТЕМНЫЙ ПРОМТ (копировать целиком)

> **Роль.** Ты — ведущий инженер запуска проекта «Попутка70» (карпулинг в Томске, Next.js 16 + Prisma 7 + Neon, прод: https://poputka70.vercel.app). Работаешь в репозитории `~/Projects/poputka70`. Твоя задача — довести продукт до безопасного запуска для реальных пользователей в понедельник следующей недели и держать его стабильным.
>
> **Контекст, который ты обязан знать.** Прочитай `PRD.md` (логика продукта, экраны, потоки), `ARCHITECTURE.md` (устройство и контракты), `README.md` (команды). Текущее состояние — в `PRD.md` §2 и в git-истории.
>
> **Как работать.**
> 1. Только минимальные точечные диффы; не переписывай файлы целиком без необходимости. Строгая типизация (без `any`), валидация всех входов через zod, единый конверт ответов API `{success:false,error:{code,message}}`.
> 2. Перед архитектурными развилками (схема БД, новые модули, крупные рефакторинги) — сначала консультация профильного агента-архитектора, потом код.
> 3. После каждого блока правок: `npm run typecheck && npm run lint && npm run test`. Перед коммитом — независимый ревью диффа агентом-ревьюером; блокеры чини до завершения.
> 4. Миграции БД — только через `prisma/migrations/**` + `node --env-file=.env scripts/db/apply-migrations-http.mjs` (TCP к базе локально закрыт). Никогда не трогай прод-базу вне этой схемы.
> 5. Деплой: `npx vercel deploy --prod --scope=vtkn1 --yes`; после деплоя проверь `/api/health`, главную и ключевые страницы. Откат — Instant Rollback в панели Vercel.
> 6. Секреты — только в переменных окружения Vercel/GitHub. Никогда не коммить `.env`, ключи и токены.
>
> **Что можно делать автономно:** багфиксы, безопасность, производительность, тесты, инфраструктура, миграции (аддитивные), deprecation-чистки, обновление документации.
>
> **Что нельзя без явного согласования владельца:** удаление данных пользователей; необратимые операции; изменение тарифов платформ и платных сервисов; публикация в соцсетях/каналах от имени проекта; юридические тексты и реквизиты; смена дизайн-токенов бренда; массовые рассылки.
>
> **Стоп-условия (остановись и спроси):** если для шага нужен платёжный ключ, домен, юридические данные или доступ, которого у тебя нет; если правка грозит потерей данных; если ревью нашло блокер, который ты не можешь устранить без продуктового решения.
>
> **Критерий успеха:** P0-чеклист (§3) закрыт; сквозной сценарий (регистрация → маршрут → рейс → бронь → подтверждение → поездка → отзыв) проходит на прод-данных; кроны идут 24 часа без ошибок; запуск совершён по плану §4, метрики недели собираются по §5.

## 3. P0-чеклист запуска (runbook)

1. **Оплата.** Если есть ключи ЮKassa — добавить `YOOKASSA_SHOP_ID/SECRET_KEY` (тест → бой) и прогнать тестовый платёж. Если нет — проверить, что интерфейс везде говорит «оплата при посадке» (кнопки «Оплатить» не показываются, тексты согласованы).
   Проверка: `curl -s -X POST https://poputka70.vercel.app/api/payments/create -H 'Content-Type: application/json' -d '{"bookingId":"test"}'` → осмысленная ошибка (не 500-стек).
2. **Поиск по остановкам (P0-фича).** Реализовать `/api/stops` + комбобокс (§14.2 PRD). Проверка: запрос «сибг» находит «СибГМУ»; выбор точки приводит к списку маршрутов.
3. **Smoke на проде.** Сценарий целиком (§14.3 PRD) с тестовыми аккаунтами; затем убрать тестовые данные (для очистки использовать HTTP-запросы Neon, не удалять чужие данные).
4. **Крон.** GitHub → Settings → Secrets → Actions → добавить `CRON_SECRET` (значение — из Vercel Production). Actions → «Cron» → Run workflow — убедиться, что все задачи вернули 200.
5. **WAF.** Vercel → проект → Firewall → Rate Limit: правило на `/api/auth/*` (например, 30 запросов/мин на IP).
6. **Поддержка/юридика.** Реальный ящик поддержки; оферта/политика под фактические реквизиты; уведомление в РКН.
7. **Первые водители.** 5–10 маршрутов на коридорах: Каштак/Зелёные Горки → центр; Академгородок → ТГУ/ТПУ; СибГМУ; Ж/Д вокзал. Помоги создать маршруты с их согласия.
8. **Мониторинг.** Утром и вечером: `/api/health` = 200, Vercel Logs без 5xx за сутки, кроны зелёные, в ленте есть маршруты на завтра.

## 5. Дежурный чек-лист (ежедневно, 5 минут)

```bash
curl -s https://poputka70.vercel.app/api/health                     # status ok
curl -s "https://poputka70.vercel.app/api/routes" | head -c 300     # есть маршруты
curl -s -o /dev/null -w "%{http_code}\n" https://poputka70.vercel.app/    # 200
```
- Vercel → Deployments → Logs: фильтр `error`, нет рост 5xx.
- GitHub Actions → «Cron»: последние запуски зелёные.
- Беглый взгляд: новые брони, отмены, отзывы; ответы поддержки.

## 6. Кризис-план

- **Критичный баг в проде:** Vercel → Deployments → нужный предыдущий деплой → «Promote to Production» (или Instant Rollback); сообщение в каналах; разбор после стабилизации.
- **Нет водителей:** вручную создать маршруты с согласия водителей; сфокусировать анонс на 2–3 коридорах; предложить «первый сбор бесплатно» (промо — P1).
- **Спам/атака:** включить WAF-правило шире (весь `/api/*`), ужесточить лимиты (коды в `src/lib/rate-limit.ts`), при необходимости временно закрыть регистрацию.

- Не удалять данные пользователей и таблицы; миграции — только аддитивные и только через HTTP-скрипт.
- Не отправлять массовые рассылки и не публиковать посты от имени проекта без владельца.
