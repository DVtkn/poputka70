# Документация по ролям — Poputka70

Версия: 17.10.2026. Для команды разработки: как система работает для каждой роли, какие экраны, API, права и ограничения.

---

## 0. Общая модель ролей

| Роль | Как получается | Что может | Что не может |
|------|---------------|-----------|--------------|
| **Гость** | Не авторизован | Поиск поездок, просмотр маршрутов, публичные профили | Бронировать, публиковать, писать отзывы |
| **Пассажир (PASSENGER)** | Авторизован, без DriverProfile | Искать, бронировать место, отменять свою бронь, оставлять отзывы, редактировать профиль | Публиковать поездки, принимать заявки, модерация |
| **Водитель (DRIVER)** | PASSENGER + DriverProfile (авто) | Всё от пассажира + публиковать поездки, принимать/отклонять заявки, видеть телефоны пассажиров после подтверждения | Модерация чужих документов, админ-действия |
| **Админ (ADMIN)** | Назначено вручную в БД | Модерация верификаций (`/admin/verifications`), просмотр всех пользователей, бан/разбан | — |
| **Поддержка** | ADMIN + доступ к почте support@ | Обработка жалоб, ручные возвраты, связь с пользователями | — |

**Правило:** один аккаунт = все роли. Водитель может быть пассажиром в чужой поездке. Пассажир может стать водителем, добавив авто.

## 1. Гость (не авторизован)

### Что видит
- Лендинг `/` — герой, форма поиска, живая статистика, лента ближайших поездок, блоки «как это работает», «почему выбирают», CTA водителя, футер.
- Поиск `/search` — подбор рейсов по направлению и дате без входа.
- Маршрут `/routes/[id]` — информация о маршруте, ближайшие рейсы.
- Поездка `/trips/[id]` — информация о поездке, цена, кнопка брони (открывает модалку входа).
- Публичный профиль `/users/[id]` — имя, рейтинги, отзывы, авто, активные маршруты.
- Юридические страницы `/legal/terms`, `/legal/privacy`, `/how-it-works`.

### Что делает
1. Вводит «Откуда» и «Куда» (комбобокс по справочнику Stop, 768 остановок).
2. Выбирает дату и количество пассажиров.
3. Нажимает «Найти попутку» → список карточек поездок.
4. Открывает поездку → нажимает «Забронировать» → модалка входа/регистрации.
5. После входа продолжает бронирование автоматически.

### API (доступно без сессии)
- `GET /api/trips` — лента и поиск по коридору ≤700 м.
- `GET /api/trips/[id]` — карточка поездки.
- `GET /api/stops?query=` — автодополнение остановок.
- `GET /api/users/[id]` — публичный профиль.
- `GET /api/health` — проверка работоспособности.

## 2. Пассажир (PASSENGER)

### Что видит (дополнительно к гостю)
- Модалка входа/регистрации (AuthModal) — без выбора роли.
- Онбординг `/onboarding` — две ссылки: «Найти попутку» / «Подвезти соседей».
- Профиль `/profile` — имя, рейтинг, меню (брони, поездки, верификация, админка).
- Мои бронирования `/profile/bookings` — предстоящие/завершённые/отменённые, разбор цены, отмена за ≥60 мин, отзыв после завершения.
- Уведомления `/notifications` — журнал событий, подписка на Web Push.
- Редактирование профиля `/profile/edit` — имя, фамилия, телефон, bio.

### Что делает
1. Регистрируется (всегда `role = PASSENGER`) → сессия → редирект в `callbackUrl` или на главную.
2. Ищет поездку → выбирает остановки посадки/высадки (bottom sheet) → нажимает «Запросить место».
3. Создаётся бронь `PENDING` → место резервируется атомарно → водителю push «Новая заявка».
4. Водитель принимает → бронь `CONFIRMED` → пассажиру push «Поездка подтверждена» + телефон водителя.
5. После поездки (`COMPLETED`) → оставляет отзыв 1–5 + комментарий.
6. Может отменить бронь за ≥60 мин до отправления → место возвращается.

### API (требует сессию)
- `POST /api/auth/register` — регистрация.
- `POST /api/auth/login` — вход.
- `GET /api/auth/me` — текущий пользователь.
- `POST /api/bookings` — создать заявку (PENDING).
- `POST /api/bookings/[id]/cancel` — отменить свою бронь.
- `POST /api/reviews` — оставить отзыв (только участник завершённой поездки).
- `GET /api/notifications` — журнал уведомлений.
- `POST /api/push/subscribe` — подписка на Web Push.
- `PATCH /api/profile` — редактировать профиль.
- `POST /api/profile/password` — смена пароля.

## 3. Водитель (DRIVER)

### Как стать водителем
1. Авторизованный пользователь переходит в `/driver`.
2. Заполняет форму «Регистрация водителя»: модель авто, номер, цвет.
3. `POST /api/driver/register` → создаётся `DriverProfile`, роль меняется на `DRIVER`, кэш сессии инвалидируется.
4. Теперь может публиковать поездки.

### Что видит (дополнительно к пассажиру)
- Кабинет водителя `/driver` — форма авто (если нет профиля) или форма новой поездки (если есть).
- Мои поездки `/profile/trips` — список рейсов, блок «Хотят поехать» (заявки пассажиров), решения accept/decline.
- Верификация `/profile/verify` — загрузка фото ВУ и авто, статус модерации, бейдж «Проверен» после одобрения.

### Что делает
1. Добавляет авто → становится водителем.
2. Публикует поездку: откуда/куда (остановки справочника), дата, время, места (1–8), цена, заметка, повтор (none/weekdays/weekends/daily).
3. Поездка создаётся со статусом `CONFIRMED` и попадает в ленту сразу.
4. Видит заявки пассажиров в `/profile/trips` → принимает или отклоняет в один тап.
5. При accept: место списывается, пассажиру push, телефон пассажира раскрывается водителю.
6. При decline: место возвращается, пассажиру уведомление.
7. Может отменить свою поездку до отправления → все брони снимаются, места возвращаются, пассажирам push.

### API (требует DriverProfile)
- `POST /api/driver/register` — стать водителем.
- `POST /api/trips` — опубликовать поездку (или серию на 2 недели).
- `POST /api/bookings/[id]/accept` — принять заявку (только водитель поездки).
- `POST /api/bookings/[id]/decline` — отклонить заявку (только водитель поездки).
- `POST /api/trips/[id]/cancel` — отменить свою поездку.
- `POST /api/profile/verify` — загрузить документы для верификации.

## 4. Админ (ADMIN)

### Как стать админом
Назначается вручную в БД (`UPDATE "User" SET role = 'ADMIN' WHERE id = ...`). Нет интерфейса самоназначения.

### Что видит
- Очередь верификаций `/admin/verifications` — табы: на проверке / одобренные / отклонённые.
- Карточки с фото ВУ и авто (через защищённый эндпоинт).
- Счётчики, пустые состояния.

### Что делает
1. Просматривает заявки на верификацию водителей.
2. Одобряет или отклоняет с комментарием.
3. Решение уходит водителю push + in-app уведомлением.
4. Все действия атомарны, повторная обработка невозможна.

### API (требует ADMIN)
- `GET /api/admin/verifications` — список заявок.
- `POST /api/admin/verifications/[id]` — одобрить/отклонить с комментарием.
- `GET /api/admin/verifications/[id]/photo` — фото документа (защищённый эндпоинт).

## 5. Поддержка

### Что делает
- Отвечает на письма support@poputka70.ru.
- Обрабатывает жалобы (модель `Complaint`).
- Оформляет ручные возвраты при отмене с оплаченным сбором (если ЮKassa подключён).
- Видит историю поездок и броней, статусы платежей.

### Ограничения
- Телефон и документы не отдаются в публичных ответах.
- Нет прямого доступа к админ-панели верификаций (только ADMIN).

## 6. Разработчик

### Стек
| Слой | Технология |
|------|-----------|
| Фронтенд/бэкенд | Next.js 16, App Router, React 19, TypeScript strict |
| Стили | Tailwind CSS 4 + дизайн-токены в `globals.css` |
| БД | PostgreSQL (Neon), Prisma 7 |
| Сессии | JWT (jose), httpOnly-cookie, роль/статус из БД (кэш 5 с) |
| Валидация | zod (все входы API) |
| Push | web-push + VAPID |
| Карта | Яндекс.Карты static-maps (без ключа) |
| Тесты | Vitest (unit), smoke-скрипт (prod) |
| Деплой | Vercel (Hobby) |

### Команды
```bash
npm install
cp .env.example .env
npx prisma generate
npm run dev              # http://localhost:3000
npm run verify           # typecheck + lint + test
npm run build            # verify + next build
node --env-file=.env scripts/db/apply-migrations-http.mjs   # миграции
node --env-file=.env prisma/seed.ts                         # сид
BASE_URL=https://poputka70.vercel.app node scripts/smoke-prod.mjs   # smoke на проде
npx vercel deploy --prod --scope=vtkn1 --yes   # деплой
```

### Соглашения кода
- TypeScript strict, **без `any`** и выдуманных интерфейсов.
- Все входящие данные — через zod-схему в `lib/schemas.ts`.
- Ответы API — через `ok()/errors` из `lib/http.ts`.
- Время — только `Asia/Tomsk` (`lib/time.ts`), не `new Date()` в бизнес-логике.
- Серверные компоненты по умолчанию; `"use client"` — только для интерактива.
- UI: токены дизайн-системы (`bg-snow`, `text-taiga`, `card`), без магических цветов.
- Тексты — по-русски, без эмодзи, без канцелярита.
- Точечные диффы, без попутных рефакторингов.
- Секреты — только в env; не коммитить `.env`.

### Git и деплой
- Коммиты: осмысленное сообщение в императиве, один логический блок на коммит.
- **Не пушить `.github/workflows/`** — нет scope `workflow` у креденшела.
- `git add -A -- ':!.github'` → коммит → push в `main` → деплой Vercel.
- Откат — Instant Rollback в панели Vercel.

### Диагностика
| Симптом | Решение |
|---------|---------|
| `ECONNREFUSED :5432` | TCP к Neon закрыт — HTTP-скрипт миграций |
| 401 на cron | нет/неверный `CRON_SECRET` (fail-closed) |
| Карта не видна | у остановок нет координат или лимит Яндекса |
| Push не приходит на iPhone | приложение не установлено на экран «Домой» |
| Дубли заявок | частичный уникальный индекс активной брони |
